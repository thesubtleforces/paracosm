# Scene Walk — step into the picture

A walk is a **real-time, navigable video** of the current scene, opened from a link in
Telegram and explored with WASD / touch for a capped minute or so. It is generated by a
world model seeded with this turn's keyframe, so it looks like the campaign's art and
moves like a place.

**A walk is spectacle, not mechanics.** Nothing the player sees or "finds" on a walk
exists in the game. The campaign files stay the only truth. Say so once, in voice, the
first time a player is offered one ("you may wander, but the story waits where you left
it").

## When to Use
- A set piece, a reveal, or first arrival in a **new region** (the establishing shot).
- On request: "look around", "can I explore this", "show me the place".
- **Never** on ordinary turns, never in rapid dialogue, never more than one per act, and
  never at all unless `PARACOSM_WALK_URL` is configured — the script tells you. If the
  campaign's walk budget (`meta.walk_budget_seconds`, default 600) is spent, decline in
  voice and offer `ooc:` to raise it.
- Party mode: **one link for the table**, each opener gets their own session, so
  `max_sessions` = number of players (cap 6). The budget is charged for all of them.

## Procedure

### 0. Turn contract first
Narration + choice block are already sent. A walk is a chaser, like art. Never block.

### 1. Keyframe (quality tier — it returns the public URL a walk needs)
```bash
bash scripts/fal_image.sh "<style prefix + scene sentence + locked descriptors>" \
  "games/<slug>/art/turn<NNN>-walk.png" landscape_16_9 quality
```
Keep the printed `url`. (The fast tier prints no URL; a walk needs one.)

### 2. Compose the manifest — from the files, never from memory
Write `games/<slug>/walks/turn<NNN>.json`:

```json
{
  "slug": "<slug>", "turn": <NNN>,
  "seed_image_url": "<fal.media url from step 1>",
  "contract": {
    "identity":    "<the PC's locked descriptor from state.json → art.character_descriptors; 'one' + subject, what must never change>",
    "camera":      "<style.md composition rule for walks; default: 'stable third-person follow camera about one meter behind, camera height and lens never change'>",
    "environment": "<state.json → location + the relevant world.md section, concrete near/mid/far details>",
    "invariants":  "<style.md 'Never' block + rating constraints, phrased as 'never ...'>"
  },
  "static_prompt": "<one sentence: the subject at rest, small idle motion>",
  "moving_prompt": "<one sentence: the subject travelling away from camera along the obvious route>",
  "actions": [
    {"label": "<choice 1, 2-3 words>", "prompt": "<complete visible action and the return to the stable pose>"},
    {"label": "...", "prompt": "..."}
  ],
  "cap_seconds": 90, "max_sessions": 1, "rating": "<meta.rating>"
}
```

Rules that make the world model behave (from the reference recipe this is built on):
- **Be unusually explicit about invariants** — subject, camera, environment, and the
  details that must not change. Positive descriptions beat negations except in
  `invariants`.
- **Actions are the choice block, rewritten as motion**: each is a complete visible
  action *and* its return to the stable pose ("she raises the lantern high, then lowers
  it and stands as before"), never just a verb. 1–4 actions; take the current choice
  block's options.
- No camera verbs anywhere except the `camera` line; no input vocabulary ("press W").
- Style prefix goes at the start of `identity`.
- Never illustrate secrets the player hasn't seen.

### 3. Sign the link
```bash
python3 scripts/walk_link.py games/<slug>/walks/turn<NNN>.json
```
Prints the URL (valid 30 minutes). On `{"error": ...}` → skip the walk silently this
turn; note the reason in the journal entry only.

### 4. Deliver
One short in-voice line with the link as its own message, e.g.
> *The fog thins for a moment. If you want to walk the causeway yourself: <url>*
> *(about a minute and a half; the story waits.)*

### 5. WRITE
Append `{turn, file, cap_seconds, max_sessions}` to `state.json → art.reactor.walks[]`;
add `cap_seconds × max_sessions` to `art.reactor.walk_seconds_used`; journal the walk in
one line.

## Pitfalls
- A walk never changes state, location, HP, inventory, or NPC dispositions. If a player
  reports something they "saw" on a walk, treat it as their imagination in voice.
- Never re-sign or extend a link on request beyond the budget; never raise
  `max_sessions` above the table size.
- Never paste the seed image URL or the manifest in chat — only the signed link.
- The page runs in the phone's browser; if it can't play (old in-app browser), the page
  itself says "open in Safari/Chrome". Don't debug it in the fiction.

## Verification
Manifest file exists under the campaign folder; the link verifies with
`walk_link.py --verify`; `walk_seconds_used` advanced; the journal has the walk line;
nothing in `state.json` besides `art.reactor` changed because of the walk.
